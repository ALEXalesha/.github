# Contributing

Thanks for looking. These projects are developed by one person, mostly for his own use, but issues and pull requests are welcome.

## Issues

A good bug report says what you did, what you expected and what happened instead, with the version (it is in the window title or the About box) and your Windows version. A screenshot helps. The interfaces are in Russian; write in English or Russian, whichever is easier.

## Pull requests

- Keep a pull request to one change. A bug fix and a refactoring are two pull requests.
- **Add a test that fails without your change.** Most projects test with random inputs (hypothesis, fast-check, FsCheck) and check invariants; a new property is even better than a new example.
- Run the project's tests before you push: the README of each project has the exact command, and CI runs the same on every pull request.
- Screenshots in the READMEs are generated by a script in `tools/`. If your change alters the window, regenerate them with that script instead of taking a screenshot by hand.
